# Cos72 验收标准（用户视角，本轮 = ME4-5.3 原型）

> 这是「做成了没有」的标准，不是技术任务清单（技术拆解见 [`tasks.md`](tasks.md)）。
> 判断依据只有一条：**这些事情能不能真的替社区操作者做掉，且他敢让它记账。**
> 「用户」= 装了 Agent24 的社区操作者（持 daemon token 的那个人），本轮是单操作者；成员身份是请求体里的 `member` 字符串（开放问题 Q1）。
> 记录日期：2026-09-29

## 一、任务能从发布走到完成

操作者代成员发布一个带积分的任务，另一个成员领取、提交，操作者在 Agent24 的审批界面（`/api/v1/module-approvals`）批准后，任务变「完成」、积分到账。

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 发布 | `POST /api/v1/cos72/tasks` 返回 201 与 `status=open`，积分 1..=1,000,000 | ⏳ T1.2.1 |
| 领取 | 只有 `open` 的任务能领；已被领的再领 → 409 | ⏳ T1.2.1 |
| 提交 | 只有领取人能提交；提交后内核里出现一条 `module=cos72`、`kind=advise`、payload 带 `award_id` 的待审批 | ⏳ T1.3.1 |
| 批准 → 完成 | 批准后 ≤ 30 秒内任务变 `completed`，领取人余额 + 奖励积分 | ⏳ T1.3.1 / T1.4.1 |
| 拒绝 | 拒绝后任务回到 `claimed`，余额不变，领取人可改后重交 | ⏳ T1.3.1 |
| 过期 | 5 分钟没人批（内核 TTL 300s）→ 这次申请作废，任务仍是 `submitted`，领取人再交一次即重新发起审批 | ⏳ T1.3.1 |
| 事件 | 每个动作在 Agent24 事件流（WS）里能看到一条 `module=cos72` 的事件 | ⏳ T1.1.1 / T1.2.1 / T1.3.1 |

## 二、积分账敢信

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 不多发 | 同一笔奖励无论重试、重启、重复提交、审批孤儿被人批准，最多入账一次 | ⏳ T1.3.1 |
| 可重算 | 余额不是存的数，而是账本回放算出来的；重启 daemon 后余额逐人一致 | ⏳ T1.3.1 / T1.4.1 |
| 不可改 | 账本行一旦写入，改和删在数据库层就会失败 | ⏳ T1.1.1 |
| 可追溯 | 每条账本行能追到 `award_id` → `task_id` → 内核 `approval_id` | ⏳ T1.3.1 |

## 三、Agent24 记得这件事，但不把它当真相

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 摘要进记忆 | 任务完成后，Cos72 自己的内核私有记忆里恰好有一条该任务的完成摘要 | ⏳ T1.3.1 / T1.4.1 |
| 不重复 | 重启、泵重试之后仍恰好一条 | ⏳ T1.3.1 / T1.4.1 |
| 真相在本地 | 删掉/读不到记忆不影响任务与余额（记忆是派生副本） | ⏳ T1.3.1 |

## 四、与 Sin90 同时装着也互不干扰

| 子项 | 要求 | 当前状态 |
|:---|:---|:---|
| 同时挂载 | `agent24 os list` / `GET /api/v1/os` 里 Cos72 与 Sin90 都是 `mounted` | ⏳ T1.4.1 |
| 记忆隔离 | Cos72 查不到 Sin90 写的记忆，Sin90 查不到 Cos72 的；各自查得到自己的（正对照） | ⏳ T1.4.1 |
| 调度隔离 | Cos72 没有调度能力（握手 Offer 不含 `_a24/scheduler/`），内核 `schedules` 表里 `owner_module=cos72` 的行为 0；Sin90 的行归 Sin90（正对照） | ⏳ T1.4.1 |

## 验收时怎么判断「好用」

1. 真实挂载黑盒一条命令跑完：`cargo test --test agent24_mount_blackbox -- --ignored --test-threads=1` 全绿（需要 Agent24 与 Sin90 检出）。
2. 批准到到账的延迟 ≤ 30 秒（轮询间隔 3 秒，留 10 倍余量）。
3. 不出事故：任何路径都不会出现「一笔奖励两条账」「未批准却到账」「Cos72 读到 Sin90 的记忆」。

## 明确不在本轮

myshop（花积分）、myvote、渠道接入（微信/Nostr）、链上桥接（AAStar MyTask 合约、AirAccount 身份）、
任务取消/退领/截止时间、多操作者与成员鉴权、前端界面、standalone 运行模式。
